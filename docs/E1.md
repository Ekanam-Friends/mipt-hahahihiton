# E1 — импорт официального корпуса

Завершён 12.11.2026 на локальном снимке загрузки от 11.11.2026. Все 20 SHA-256 повторно сверены с манифестом; повторная загрузка Drive не выполнялась.

## Результат

- **20/20 файлов**: 9 PDF, 8 DOCX, 3 XLSX; **1702 непустых фрагмента**, ошибок импорта нет.
- PDF: **79 страниц**, из них **44 OCR-страницы**; номера сохранены. Страницы с текстом короче 40 символов проходят русский OCR.
- DOCX: абзацы, стили заголовков, таблицы и приложения извлекаются в порядке XML. Вложенные таблицы и буквенные номера приложений сохраняются. Объединённые ячейки обходятся по физическим XML-ячейкам, без повторения текста вертикальных объединений; одинаковые значения разных ячеек не удаляются.
- XLSX: все непустые ячейки всех листов, включая скрытые; адреса, объединённые диапазоны, подписи, формулы и сохранённые значения. Найдено **854 формулы**, у всех отсутствуют сохранённые результаты: 6 в бланке РЦНИ и 848 в смете 2019. Эти два файла имеют статус `warning`; результаты не выдумываются. Формулы, макросы и внешние ссылки не исполняются; `keep_links=False`.
- [Связи приложений](../data/official/relations.json) содержат основание каждой связи. Для XLSX 2019 родительский приказ не установлен однозначно. Связь бланка с приказом не означает действующую редакцию — применимость относится к E2.

Доказательства: [отчёт импорта](../data/official/import-report.json), [независимая сверка](../data/official/e1-validation.json), [тесты](../tests/test_ingest.py). У каждого файла в отчёте: статус, хеш, число фрагментов/блоков, пустые блоки/страницы, OCR-страницы, формулы, предупреждения и факт использования кэша.

## Адресация и просмотр

ID фрагмента: ID документа + SHA-256 от адреса, пункта и текста (20 hex-символов); одинаковые фрагменты одного адреса получают различающий суффикс. Повторная обработка неизменного снимка сохраняет все ID; изменение текста/адреса создаёт другой ID.

У PDF есть начальная страница и диапазон `source_start/source_end`; у DOCX — XML-адреса начала/конца и список охваченных абзацев/ячеек, без вымышленных номеров страниц. У XLSX — лист, диапазон и данные каждой ячейки строки. Длинный фрагмент может ссылаться на несколько блоков.

Импорт создаёт `data/official/view/<id>.html`. Поле `meta.view_path` ведёт к выделяемому якорю; CLI search печатает путь. HTML открывается в браузере, содержит исходные блоки с адресами и ссылку на оригинал. Это текстовый просмотр, не копия оформления Office. Текст экранирован; сетевых скриптов нет. Интеграция в веб-ответ — E4.

Оригиналы, кэш, текст, фрагменты и HTML локальны и исключены из Git. Код, связи и отчёты публикуются для воспроизведения.

## Проверки и ограничения

`scripts/verify_e1.py` независимо читает XML всех 8 DOCX и сопоставляет каждый непустой абзац, включая таблицы, с извлечением в исходном порядке (пробелы/разрывы нормализуются). Для 3 XLSX проверяется каждая непустая ячейка; для PDF — число страниц и точное совпадение текстового слоя на страницах без OCR. Проверяются все локальные якоря, уникальность ID и их сохранность после повторного импорта.

Выборочно просмотрены: приказ 889-1 (заголовок и пункты), бланк 1а, таблицы финансовой структуры; XLSX РЦНИ (E1 — «Приложение № 1б», F13 — формула без результата), XLSX 2019 (листы и формулы), PDF 460-1 (страница 2 — визуальная сверка скана с OCR). Изображение скана локально: `data/official/evidence/e1-scan-page2.png`.

В скане читаются название, раздел 1 и определения руководителя/карточки проекта. **Рукописные дата и номер в шапке распознаны неточно**; возможны ошибки отдельных символов. Даты/редакции нельзя получать из такого текста без сверки с оригиналом. E1 не подтверждает посимвольную точность OCR и качество ответов RAG; поиск, редакции и процедуры проверяются в E2–E5.

**12 тестов прошли.** Проверены добавление каждого формата только через манифест с появлением в поиске; сохранённый/отсутствующий результат формулы; порядок таблиц и вертикальные объединения; адреса OCR; стабильность ID; битый файл вместе с исправным; восстановление файла; повторная поломка с исключением старого текста/фрагментов. При ошибках ingest сохраняет результаты остальных файлов, удаляет устаревший просмотр повреждённого файла и возвращает код 1.

Кэш проверяет фактический SHA-256 и версию извлечения. Изменение файла, повреждённый кэш или `--force` вызывают повторное извлечение. Старый текст после ошибки не попадает в индекс. Старый текстовый кэш вспомогательного корпуса не считается доказательством: новый импортёр сначала извлекает его заново.

## Воспроизведение

Из корня репозитория: Python 3.10+, зависимости `requirements.txt`, Tesseract и `rus.traineddata` в `.tessdata` либо `TESSDATA_DIR`.

```powershell
python -m pip install -r requirements.txt
# Если оригиналы отсутствуют — загрузить официальный корпус.
python scripts/download_official.py
python -m regnav --data data/official ingest --workers 2
python scripts/verify_e1.py
python -m pytest -q
python -m regnav --data data/official search "Как скорректировать смету?" -k 5
```

Новые файлы: добавить строку манифеста (`id`, `title`, `local_path`, `url`), повторить ingest. Путь абсолютный, относительно манифеста либо корня проекта. Дополнительные поля сохраняются; отношения задаются `relations` в записи или необязательным `relations.json` рядом с манифестом. Допуск новых документов во внешнее API определяется отдельно.
