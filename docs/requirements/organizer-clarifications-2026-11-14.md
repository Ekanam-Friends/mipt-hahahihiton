# Уточнения организаторов от 14.11.2026

Источник: переписка «ИИ в системе управления МФТИ» в ответ на вопросы Михаила, переданная участником команды 14 ноября. Это уточнения, а не новый формальный регламент мероприятия.

- Целевые RPS, TTFT, latency, стоимость и бюджет API не заданы. Приоритет: качество поиска, правильность ответов и стабильность; скорость и низкая стоимость — преимущество.
- Локальные модели и внешние API допустимы. Во внешние API разрешены только открытые, неконфиденциальные данные.
- MVP: работающий сервис, понятный ответ, найденные документы и источники; последовательность действий для процедурного вопроса; честный отказ при отсутствии сведений.
- BM25, гибридный поиск, agentic RAG, GraphRAG, дополнительные модели и готовые open-source решения допустимы. Баллы даются за результат, а не число технологий. Обязательного baseline нет.
- Фиксированного набора метрик нет. Важны правильные документы, отсутствие выдумок и корректные ссылки; измерения и тесты полезны.
- Самооценка сама по себе не даёт баллов; полезность нужно показать на контроле качества и выявлении ошибок.
- Ориентир — предоставленный набор документов; будущий объём не определён. Желательно добавлять документы без переделки системы.
- Управление правами, изменение/удаление документов и внешние действия не входят в обязательный MVP. Обработка ошибок, некорректных вопросов, нехватки информации и противоречий важна.
- Решение должно воспроизводимо запускаться по инструкции; команда должна объяснить архитектуру и продемонстрировать результат.

Вывод для текущего релиза: исправление доступности, воспроизводимости, дат, достаточности поиска и доказательств приоритетнее добавления нового ML-стека. Эти уточнения не подтверждают качество конкретных ответов и не заменяют приёмку по источникам.
