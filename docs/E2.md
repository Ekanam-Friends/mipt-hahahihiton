Эталоны подготовлены по текстам источников до настройки ранжирования: ожидаемый документ, стабильный ID фрагмента, опорная цитата, дата вопроса, ожидаемая применимость и обязательные элементы будущего ответа. Каждый из 20 документов представлен обязательным источником хотя бы одного вопроса. Проверяется попадание **каждого** обязательного фрагмента, а не любого подходящего документа. Проверены локальные HTML-якоря эталонов.

## Поиск и контекст

К исходным BM25 и символьным n-граммам добавлены локальные раскрытия сокращений, словарь парафразов, нормализация номеров приказов, канал BM25 по содержимому без повторяемого названия документа и приоритет точных адресов ячеек. Сохраняются каналы исходного запроса. Результаты объединяются RRF.

Составные вопросы разбиваются по вопросительным знакам, точкам с запятой и координированным вопросам. Короткие части с местоимениями сохраняют предшествующий контекст; самостоятельные вопросы не получают весь текст первой части. Списки вроде «карточка и скан договора» не разделяются. Это детерминированная декомпозиция с ограниченным словарём, а не произвольное понимание языка.

Для каждой части выделяется собственный бюджет кандидатов: в приёмке **top-10 на часть**, с объединением без дубликатов. Кандидаты не обрезаются единым лимитом из шести фрагментов. Отдельно добавляются доказательства дат и расхождений из реестра. Поэтому 26/26 — результат полного контура декомпозиции, поиска и добавления обязательных доказательств; это **не** утверждение о top-10 целого вопроса и **не** изолированная оценка нового ранжировщика. В отчёте есть трасса каждой части, все ID, адреса, оценки и время поиска.

Эмбеддинги не включены: локальный контур проходит текущую приёмку; доказательства пользы конкретной модели эмбеддингов нет. Внешние API в этой проверке не использовались. Символьный канал не называется семантическими эмбеддингами.

## Применимость и расхождения

Реестр хранит дату издания отдельно от даты начала действия, неизвестные даты — как `null`; дату загрузки не использует как дату действия. У фактов есть цитаты и ID фрагментов. Связи различают новую редакцию, частичное изменение, отмену, дополнение, реализацию и приложения; отсутствующие в корпусе приказы обозначены явно. При изменении хеша источника использование старого реестра блокируется до повторной проверки.

- **3065-1:** новая редакция регламента открытия ФЛС с **01.12.2021**, по пункту 1; он изменяет редакцию, утверждённую 1385-1, которого в корпусе нет.
- **460-1:** начало действия регламента **01.05.2017** читается в пункте 4. Рукописные реквизиты OCR ненадёжны. Полная отмена именно этого документа предоставленными материалами не доказана.
- **700:** порядок присвоения номера действует с утверждения **28.12.2024**, по заключительным положениям. Он не объявлен автоматической заменой всей процедуры открытия ФЛС.
- **794-1:** отменяет 1469-1 и утверждает бланки 1а/1б; отдельная дата начала действия не установлена. **889-1:** вводит функционал с подписания **04.04.2023** и утверждает инструкцию; это связанный документ, а не автоматическая отмена 794-1.
- **5990-1:** новый регламент заимствования с подписания **03.11.2026**, отмена 1465-1 подтверждена пунктом 1. Запрос на 02.11.2026 вызывает уточнение, а не применение будущей редакции.
- **3614-1 / 3699-1:** период планирования 2026–2028 не подменяет дату действия. Срок 01.10.2025 в бюджетном приказе не переносится автоматически на 2026 год.
- У командировок, подбора персонала и поселения есть незаполненные реквизиты утверждения. У XLSX 2019 родительский приказ не установлен; связь с отменённым 1469-1 не выдумывается. Другие неподтверждённые даты явно отмечены как неизвестные.

В старом порядке ФЛС фигурирует ПФО, в 3065-1 и 700 — ФЭУ. Это зарегистрировано как **возможное расхождение маршрутов**, а не доказанная полная отмена старого документа. Вывод включает обе стороны, ссылки и опорные цитаты. Подтверждённый конфликт или неприменимость на заданную дату дают `clarify`; неизвестная применимость и возможное расхождение показываются явно в `applicability` и `warnings`. Старую эвристику названий оставили только как дополнительный сигнал.

## Воспроизведение

В рабочем окружении исполняемый файл Python из прежней `.venv` ссылается на недоступный WindowsApps Python. Проверки выполнены установленным Python 3.10 с уже имеющимися зависимостями `.venv/Lib/site-packages`:

```powershell
$env:PYTHONPATH = '.venv\Lib\site-packages'
$env:PYTHONIOENCODING = 'utf-8'
& C:\Users\Dell\AppData\Local\Programs\Python\Python310\python.exe scripts/verify_e2.py
& C:\Users\Dell\AppData\Local\Programs\Python\Python310\python.exe -m pytest -q
```

В исправном Python-окружении с зависимостями `requirements.txt`:

```powershell
python scripts/verify_e2.py
python -m pytest -q
python -m regnav --data data/official search "Кто присваивает номер ФЛС по приказам 460-1, 3065-1 и распоряжению 700?" -k 10
python -m regnav --data data/official ask "С какой даты действует приказ 5990-1?" --as-of 2026-11-02 --json
```

`verify_e2.py` возвращает 1 при потере любого обязательного фрагмента или провале проверок применимости. `scripts/build_e2_fixtures.py` сохраняет ручные аннотации по проверенным текстовым опорам; это не автоматическое определение юридической применимости новых документов. При обновлении корпуса аннотации и реестр нужно пересмотреть.

## Границы результата

Набор небольшой и использовался при настройке: **26/26 не является независимой оценкой на неизвестных вопросах**. Негативные вопросы, смысловая подтверждённость каждого действия, полный порядок процедуры, устойчивость генерации и веб-переходы проверяются в E3–E5. Поле `required_elements` фиксирует будущую приёмку ответа, но этот отчёт не оценивает её выполнение. Извлекающий режим по-прежнему выдаёт выдержки и может ограничить число шагов; он не принят как полноценная многодокументная процедура.
