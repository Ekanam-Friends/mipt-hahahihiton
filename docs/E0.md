# E0 — входные данные и условия разработки

Проверено 11 ноября 2026 года. Дедлайн: **14 ноября 2026, 23:59 МСК**. Основание: подтверждение участника команды и страница `/todo` в авторизованном кабинете.

## Сдача и демонстрация

Страница [загрузки решения](https://reg.hack80.phystech-union.org/submitsolution) открыта и проверена без отправки формы:

| Поле | Условие, показанное в кабинете |
|---|---|
| Задача | «Навигатор сотрудника по непрочитанным регламентам» |
| Краткое описание | Текст до 500 символов |
| GitHub | Ссылка на публичный GitHub с кодом решения, отмечено `*` |
| Развёрнутое решение | Ссылка, отмечено `*` |
| Скринкаст | Ссылка на демо не более 3 минут |
| Презентация | Ссылка на PDF или PPTX, отмечено `*` |

На проверенной форме у описания и скринкаста нет звёздочки; в план сдачи всё равно включены оба материала. Форма принимает ссылки, а не архив кода. Требования о пароле демо, конкретном хостинге и длительности устной защиты на форме не указаны. Не приписываем им вымышленные ограничения. По описанию кейса топ-3 по технической оценке приглашаются на защиту; там нужны рабочая демонстрация и возможность тестирования жюри. Дата и регламент устного выступления остаются задачей E6 после приглашения.

На `/todo` показаны выполненными подтверждение почты, данные участника, команда, заявка и подтверждение участия. Решение не отправлялось. Исходные критерии: [описание кейса](requirements/case-source.txt).

## Официальный корпус

Источник: [папка организаторов](https://drive.google.com/drive/folders/1aiZJAAns_mM5amYpxwfflWu64ZE7KIcy).

- Получено **20 из 20** файлов: **9 PDF, 8 DOCX, 3 XLSX**, **28 469 871 байт**.
- Каталог `data/official/raw/` хранит оригиналы под Drive ID с исходным расширением; исходные имена сохранены в [манифесте](../data/official/manifest.jsonl).
- Манифест содержит URL, ID, имя, размер, SHA-256, время загрузки/проверки UTC, формат, доступ и статус обработки. Дата публикации не известна и не подменяется датой загрузки.
- [Отчёт загрузки](../data/official/download-report.json); локальная копия HTML списка — `data/official/evidence/folder.html`.
- Все PDF открылись в PyMuPDF, все DOCX/XLSX прошли проверку ZIP/CRC и наличия XML соответствующего формата. Это проверка целостности контейнеров, а не качества извлечения текста или формул.
- Состав совпадает с перечнем кейса; сокращение «конц зала» в фактическом имени соответствует «концертного зала» в описании. Повторяющихся Drive ID нет.
- Статус каждого файла: скачан, **не индексирован**. Разбор, OCR и XLSX относятся к E1. Ранее собранный корпус mipt.ru хранится отдельно.

Повторить загрузку и верификацию из корня репозитория:

```powershell
.venv\Scripts\python.exe scripts/download_official.py
```

Нужны зависимости из `requirements.txt`. Оригиналы и HTML-снимок остаются локально и исключены из Git; манифест, контрольные суммы и загрузчик публикуются для воспроизводимости. При изменении содержимого Drive следует создать новый снимок и сравнить хеши; повторный запуск не перезаписывает уже скачанные файлы.

## Допуск данных

11.11.2026 пользователь подтвердил допустимость всех материалов официального кейса и разрешил действия для E0. Это основание записано в каждой строке манифеста: `external_api_allowed: true`. Допуск относится к 20 источникам этого снимка, а не ко всем будущим документам. Ограничение организаторов «только открытые / неконфиденциальные данные через внешние API» сохраняется. Ключи, личная переписка и данные кабинета не являются частью корпуса.

Ключей GigaChat / OpenAI-совместимого API в переменных окружения текущего процесса не найдено. Для E0 выбран локальный OpenAI-совместимый сервер: **llama.cpp b12284 + Qwen2.5-1.5B-Instruct Q4_K_M**. Он не требует ключа и не отправляет документы внешнему провайдеру. Небольшая модель выбрана для проверяемого запуска на имеющихся 8 ГБ RAM; это техническая базовая конфигурация, качество полного RAG проверяется отдельно в E2–E5.

Источники дистрибутивов: [llama.cpp b12284](https://github.com/ggml-org/llama.cpp/releases/tag/b12284), [Qwen GGUF](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF/tree/91cad51170dc346986eccefdc2dd33a9da36ead9). Версии и SHA-256 закреплены в `scripts/setup_local_model.ps1`. Веса занимают 1 117 320 736 байт. Перед запуском установочный скрипт проверяет хеши.

```powershell
# Получение runtime и весов; повторная загрузка не нужна при совпадающих SHA-256
.\scripts\setup_local_model.ps1
# Запуск в отдельном терминале, остановка Ctrl+C
.\scripts\start_local_model.ps1
# Проверка локального API по фрагменту официального документа
.venv\Scripts\python.exe scripts/smoke_local_model.py
```

Сервер слушает только `127.0.0.1:8087`, контекст 4096, 4 CPU-потока, без GPU. Конфигурация адаптера приложения: `REGNAV_LLM=openai`, `OPENAI_BASE_URL=http://127.0.0.1:8087/v1`, `OPENAI_API_KEY=EMPTY`, `OPENAI_MODEL=regnav-local`. В `.env` автоматически ничего не загружается; значения задаются в окружении процесса. Шаблон — [.env.example](../.env.example).

**Проверка выполнена 11.11.2026:** `/health` вернул `ok`, локальный `/v1/chat/completions` сформировал непустой ответ по фрагменту официального приказа № 794-1. [Машиночитаемый отчёт](../data/official/model-smoke.json) сохраняет ответ и явно указывает `quality_acceptance: false`: это проверка запуска/API, а не приёмка достоверности ответа или качества RAG. SHA-256 весов совпал с официальным: `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`. Установочный скрипт повторно проверен на скачанных файлах без новой загрузки. После проверки временный сервер остановлен; для дальнейшей разработки запускайте его указанной командой.
