Официальный снимок получен **11.11.2026**. Дата загрузки не равна дате действия нормы. Linux и Windows используют разные версии OCR: количество и хеши фрагментов после нового извлечения могут отличаться. В прод подключён подготовленный и ранее сверенный снимок с 1702 фрагментами; новый Linux-импорт проверен отдельно, без незаявленной подмены рабочего индекса.

## Исправления, найденные при воспроизведении

1. OCR страницы 2 регламента ЦОД: Linux уже распознал «7 лет» верно, но распознал цифру 1 как `|` в сроке виртуального сервера. Коррекции привязаны к SHA-256 оригинала и странице. Принимается как исправляемая строка, так и явно предусмотренное уже корректное извлечение; иные изменения, неоднозначные совпадения и другой источник отклоняются. Сохранён первый непрошедший отчёт, после исправления импорт повторён полностью.
2. Копирование статических файлов с Windows сохраняло недоступные непривилегированному пользователю права каталогов. Dockerfile нормализует права кода и ресурсов перед запуском. После пересборки главная страница отдаёт HTTPS 200; серверные тесты прошли повторно.
3. Старый inode bind-mount Caddy не совпадал с актуальным файлом на хосте. Актуальный конфиг передан через stdin, проверен и загружен без перезапуска остальных приложений. Файл хоста также содержит новый маршрут.

## Сервер и доступ проверяющего

Демо: **https://ai-assist.ekanamfriends.ru**. Отдельный Compose-проект `/opt/mipt-regnav/release`, модель в `/opt/mipt-regnav/models`, состояние сессий в `/opt/mipt-regnav/state`. Существующие контейнеры Ikanam и MGIMO-LMS не перезапускались. CPU-модель ограничена 3 CPU / 4 ГиБ, веб — 0,75 CPU / 768 МиБ. Образ llama.cpp закреплён digest, веса Qwen3-4B — SHA-256. Модель доступна только во внутренней сети контейнеров. Веса, исходный корпус и сессионная БД в публичный Git не входят.

`mipt-review` создан с отключённым парольным входом и без ключей. **Вход пока не активирован:** нужен публичный SSH-ключ проверяющего. ForceCommand запускает ограниченный просмотрщик в контейнере без сети, без capabilities, с файловой системой и папкой релиза только для чтения. Разрешены `help`, `pwd`, `cd`, `ls`, `cat`, `head`, `tail`, `grep`, `find`, `wc`, `sha256sum`, `exit`. Не доступны произвольные программы, shell, Docker API хоста, туннели и остальные проекты. Проверены чтение README и отклонение `/etc` и выхода через `..`; реальный SSH-вход ключом пока не проверен.

## Воспроизведение

Из корня подготовленного релиза:

```sh
python scripts/verify_e5.py
python scripts/verify_e3_evidence.py data/official/e3-current-answer-report.json data/official/e3-current-extra-report.json --output data/official/e5-checks/evidence.json
python scripts/audit_public_release.py
```

Для Linux-проверок используются `scripts/verify_e5_import.py` и `scripts/verify_e5_clean_search.py` в контейнере без сети, с подготовленными оригиналами read-only и отдельным `/out`. Свежие ответы собирает `scripts/verify_e3.py --base-url http://model:8087/v1`; внутреннее имя модели должно быть явно разрешено через `REGNAV_LOCAL_MODEL_HOSTS=model`. В отчётах сохраняются хеши реализации, корпуса, весов, промпты, ответы, статусы и время.
