# E4 — интерфейс, надёжность и Docker

**Техническая часть Е4 по ROADMAP завершена 13.11.2026.** Пользователь отделил полный перенос кабинетов MGIMO-LMS: [backlog](cabinets-backlog.md). Первоначальная оболочка 13 ноября содержала демо-вход, главную, профиль и ассистент. **14 ноября интерфейс переделан по MGIMO-LMS:** сохранены разделы кабинета, неработающие показывают недоступность в рамках хакатона; ассистент доступен в сервисах и плавающем чате. Текущая сверка и доказательства — [cabinet backlog](cabinets-backlog.md). Приведённые ниже 109 тестов и Docker-проверки относятся к версии 13 ноября; новую сборку контейнера это обновление не подтверждает. Независимая приёмка другим участником и новые вопросы остаются E5.

## Реализовано

- FastAPI и локальные HTML/CSS/JS: вопрос, краткий ответ, шаги с ответственными/сроками/документами, доказательства, конфликты, пробелы, предупреждения и дата загрузки снимка. Пять статусов E3 отображаются отдельно.
- Точный фрагмент по HTML-якорю и скачивание оригинала после входа; только известные документы внутри корпуса. Просмотр изолирован CSP; скрипты из документов не выполняются.
- Уточнение с историей до шести реплик, дата применимости, загрузка с блокировкой повторной отправки, сброс, ошибка и повтор без потери вопроса. История — в памяти вкладки, очищается при выходе/обновлении.
- Валидация вопроса 1–8000 символов, даты и истории; ограничение объявленного размера HTTP-тела, таймаут, один активный запрос. После таймаута Python-поток заканчивает работу: слот остаётся занят до окончания, повтор получает 429. Запускать с одним worker.
- Безопасные ошибки индекса, провайдера и генерации. Технический сбой возвращает HTTP 503 / `error`, а не отсутствие регламента; внутренняя диагностика проверки не показывается.
- Два вымышленных профиля SQLite, серверные сессии на восемь часов. В БД хеш токена; cookie HttpOnly/SameSite=Strict, Secure при HTTPS; выход отзывает сессию. Выбор аккаунта без пароля — демонстрационный вход, не промышленная аутентификация.
- Dockerfile Python 3.12, Tesseract и `rus`/`eng`, проверенные версии основных библиотек в `constraints-web.txt`. UID 10001, корпус read-only, сессии в отдельном томе, корневая ФС read-only, healthcheck индекса. Корпус, модель и секреты в build context не входят.
- Compose, конфигурация окружением, `.env.example`, команды импорта, сборки, запуска, проверки, перезапуска и остановки в [README](../README.md).

## Локальный режим

`REGNAV_LOCAL_ONLY=1` по умолчанию. Внешний провайдер и неизвестный `REGNAV_LLM` отклоняются до создания клиента. Для локального OpenAI-совместимого сервера разрешены loopback IP или явно доверенные `REGNAV_LOCAL_MODEL_HOSTS`; прокси игнорируются, HTTP-перенаправления не выполняются. Профиль пользователя модели не передаётся. Внешний API требует явного `REGNAV_LOCAL_ONLY=0` и отдельной проверки допуска документов и вопроса.

Базовый Compose использует `extractive`, без модели: выдержки со статусом частичного ответа. JS/CSS локальные. Браузерный журнал содержит только свой origin, включая документы. В тесте HTTP-сценариев официального корпуса попыток `socket.connect/connect_ex` не было: любое соединение после запуска тестового ASGI-loop провалило бы тест. Это проверка сценариев, не системный перехват всех пакетов машины.

Docker Desktop не опубликовал порт первоначальной `internal`-сети; финальный Compose использует bridge с портом только на `127.0.0.1`. Это не сетевой firewall. Изолированная проверка OCR/импорта выполнена отдельно с `--network none`.

Подготовка окружения использует Docker registry, Debian APT, PyPI/выбранное зеркало, загрузчик корпуса и при необходимости установщик модели. Они не запускаются при веб-запросе. PyPI в этой сессии давал TLS EOF; сборка прошла через HTTPS-зеркало TUNA без отключения проверки сертификатов.

## Воспроизведение

Основные команды — [README](../README.md). Дополнительные проверки после сборки:

```powershell
.venv\Scripts\python.exe -m pytest -q
node --check regnav/web/static/app.js
New-Item -ItemType Directory -Force data/official/e4-checks | Out-Null
docker run --rm --network none -v ./scripts:/qa:ro -v ./data/official/e4-checks:/out regnav:e4 python /qa/verify_e4_container.py
# После docker compose up -d --wait:
.venv\Scripts\python.exe -X utf8 scripts/verify_e4_live.py --url http://127.0.0.1:8000
# Необязательная dev-зависимость Playwright + установленный Chrome:
.venv\Scripts\python.exe -X utf8 scripts/verify_e4_browser.py --url http://127.0.0.1:8000
docker compose down
```

Дополнительный `compose.local-model.yaml` синтаксически проверен; соединение контейнера с моделью на хосте не проверялось. Для локального генеративного режима используйте два локальных процесса по README/E3. Другая физическая машина, независимый вопрос и публичное демо остаются Е5.
