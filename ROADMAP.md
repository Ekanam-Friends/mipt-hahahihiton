# Roadmap до полной версии

Состояние на **12.11.2026**. Цель — все требования [кейса](docs/requirements/coverage.md), 100 технических и 30 отраслевых баллов. Баллы — ориентир приоритета, не обещание результата. Галочки означают пройденную приёмку с сохранённым доказательством, а не наличие файла или запуск скрипта.

Дедлайн загрузки — **14 ноября 2026 года, 23:59 МСК**, подтверждён участником команды 11 ноября. Дата защиты неизвестна. Поэтому демонстрацию и материалы готовим к сдаче, на период после неё оставляем только репетицию и разрешённые организаторами изменения. Для текущей работы исполнение по направлениям закреплено за Codex, приёмка и сдача — за Олегом Поповым; подробности в [E0](docs/E0.md). Даты ниже — целевой график, не оценка гарантированной трудоёмкости.

## E0. Зафиксировать вход и ограничения — 11 ноября

- [x] Сохранить описание и состав официальной папки; перенести все критерии в матрицу.
- [x] Подтвердить дедлайн загрузки: 14 ноября 2026 года, 23:59 МСК (подтверждение участника команды 11 ноября).
- [x] Проверить формат загрузки и условия демонстрации в личном кабинете.
- [x] Распределить владельцев направлений: данные, поиск/ответ, интерфейс/развёртывание, качество/защита.
- [x] Скачать официальный корпус в отдельный каталог. Реестр: исходное имя, ID, URL, SHA-256, время загрузки, формат, статус доступа и обработки. Сверить 20 ожидаемых файлов с фактически полученными.
- [x] Уточнить допустимость передачи каждого источника во внешний API. До подтверждения использовать локальную обработку; выбрать и проверить доступную локальную модель либо допустимый API.

Приёмка: воспроизводимый снимок корпуса, ни один файл не потерян; известны сроки и способ запуска. Публичный корпус mipt.ru не подменяет официальный. Зависимости: доступ к папке, вычислительные ресурсы или разрешённый провайдер.

**E0 завершён 11.11.2026.** Доказательства и команды воспроизведения: [docs/E0.md](docs/E0.md). Корпус: 20/20 файлов, хеши и форматы проверены; локальный API модели ответил по официальному документу. Приёмка качества RAG относится к следующим этапам.

## E1. Полный импорт PDF, DOCX, XLSX — 11–12 ноября

- [x] Адаптер официального манифеста; импорт новых файлов без изменения основной логики.
- [x] PDF: текстовый слой, OCR, страницы, заголовки и пункты; DOCX: абзацы, заголовки, таблицы и приложения.
- [x] XLSX: листы, подписи, таблицы, адреса ячеек, формулы и сохранённые значения. Отдельно обозначать отсутствующие результаты формул; не исполнять макросы и внешние ссылки.
- [x] Стабильные ID фрагментов и ссылки на оригиналы/локальный просмотр; сохранять структуру и связи приложений с приказами.
- [x] Отчёт импорта: успешно/ошибка/предупреждение по каждому файлу, OCR-страницы, пустые фрагменты, повторная обработка исправленных файлов.

Приёмка: для всех 20 файлов есть проверенный результат извлечения либо явно разобранная ошибка с исправлением до финальной сдачи. Вручную сверены примеры каждого формата, скан и таблица. Повреждённый тестовый файл не прерывает импорт других. Покрытие T1, R4. Зависит от E0.

**E1 завершён 12.11.2026.** Импортированы 20/20 файлов, 1702 фрагмента; 44 OCR-страницы, 854 формулы с явно отсутствующими сохранёнными результатами; ошибок нет, 2 предупреждения. Проверки и ограничения: [docs/E1.md](docs/E1.md), [отчёт](data/official/import-report.json), [сверка](data/official/e1-validation.json). 12 тестов прошли.

## E2. Поиск, редакции и несколько источников — 12 ноября

- [x] Эталонные вопросы по каждой теме; ожидаемые документы, фрагменты, даты применимости и обязательные элементы ответа.
- [x] Улучшить гибридный поиск по результатам эталонов: парафразы, номера, аббревиатуры, длинные и составные запросы. Подключить эмбеддинги, если сравнение с baseline подтверждает пользу и соблюдены ограничения данных.
- [x] Разбивать составной вопрос на подзадачи, собирать доказательства по каждой; не обрезать важную норму общим лимитом контекста.
- [x] Реестр редакций: даты вступления в силу, изменения/отмены, связи приказов и приложений. Не считать дату загрузки датой действия; более поздний файл не всегда заменяет старый целиком.
- [x] Показывать конфликт с обеими ссылками; при неизвестной применимости — уточнение или явная неопределённость.

Приёмка: правильные источники и фрагменты для каждой части контрольных вопросов, актуальная норма подтверждена метаданными/текстом. Сохранён отчёт поиска, включая ошибки. Покрытие T2, T4.3, R6. Зависит от E1.

**E2 завершён 12.11.2026.** На официальном снимке от 11 ноября найдены все обязательные документы и фрагменты **26/26** эталонов (baseline — 23/26 по фрагментам); реестр 20 документов, проверка дат и обеих ссылок при расхождении, 23 теста. Неизвестная применимость обозначается явно. Эмбеддинги не подключены без доказательства пользы. Доказательства и границы: [docs/E2.md](docs/E2.md), [отчёт](data/official/e2-search-report.json). ## E3. Краткий ответ и полный проверяемый порядок — 12–13 ноября

- [x] Собирать все обязательные шаги по нескольким источникам; для справочного вопроса не выдумывать процедуру.
- [x] Различать отсутствие ответа, частичный ответ, неоднозначность и технический сбой. Не выдавать сбой модели/индекса за отсутствие регламента.
- [x] Защитить генерацию от инструкций в извлечённых документах; ограничить контекст и валидировать JSON/ссылки.

Приёмка: ручная сверка с эталонами на официальном корпусе; каждый существенный вывод имеет доказательство, процедура полна и логична. Отдельные проверки негативных, частичных и конфликтных случаев. Неподтверждённое утверждение блокирует принятие соответствующего сценария. Покрытие T3, T4, R1–R7. Зависит от E2.

## E6. Демонстрация и защита — материалы к 14 ноября, репетиция после приглашения

- [ ] Показать основной сценарий, несколько документов, XLSX, честный отказ и конфликт; дать жюри самостоятельно протестировать решение.
- [ ] Реализовать и показать ценность дополнительных возможностей: уточнение контекста сотрудника и сравнение редакций. Одного плана этих функций недостаточно для I2.1.
- [ ] Подготовить рассказ: задача → решение → живой сценарий → проверяемость → измеренное качество → ограничения → внедрение.
- [ ] Реалистичный план внедрения: владелец корпуса, согласование доступа, обновления/переиндексация, локальная модель и ресурсы, контроль качества, мониторинг и обратная связь.
- [ ] Репетиция с резервной записью демонстрации и локальным запуском; проверить формат и продолжительность выступления у организаторов.

Приёмка: проверяющий воспроизводит сценарий без помощи автора; полезные дополнения работают; утверждения о качестве подтверждаются отчётом. Покрытие I1–I3.

## Риски и порядок решений

1. **Неясен статус данных или нет доступной модели.** Проверить в E0; локальный извлекающий режим годится как baseline, но его полноту и применимость нельзя объявлять равной финальной генерации.
2. **Таблицы/сканы не извлеклись.** Исправить импорт до настройки поиска; не исключать неудобные файлы молча.
3. **Цитаты есть, процедура неверна.** Проверять смысл и полноту отдельно от совпадения текста.
4. **Не успеваем.** Сократить инфраструктурную сложность и оформление, сохранить все требования. Переносить за сдачу только необязательные улучшения, не выдавая неполную версию за готовую.

## После хакатона

Контроль доступа по ролям, регулярная синхронизация источников с историей изменений, расширение эталонов с владельцами регламентов, мониторинг качества, оценка нагрузки и стоимости. PostgreSQL/векторное хранилище добавлять при подтверждённой необходимости. Переиспользование RAG-ядра в MGIMO-LMS — отдельная интеграция после проверки качества текущего решения.
